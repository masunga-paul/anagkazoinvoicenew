# Anagkazo Autoparts — Tyre ERP & Financial Analytics

Production-grade Commercial Tyre ERP, Automated Invoicing, Stock Intake, and Multi-Tier Client Financial Intelligence System for **Anagkazo Autoparts Ltd (Kariakoo, Dar es Salaam, Tanzania)**.

Built with **Laravel 12**, **Livewire 3**, **Alpine.js**, **Tailwind CSS**, and **DomPDF**.

---

## 🚀 One-Click Railway Deployment Guide

This project is containerized with a production multi-stage `Dockerfile` and configured with `railway.json`.

### Step 1: Push Repository to GitHub
```bash
git init
git add .
git commit -m "feat: initial production-ready Anagkazo ERP release"
git branch -M main
git remote add origin https://github.com/<your-username>/<your-repo>.git
git push -u origin main
```

### Step 2: Deploy on Railway
1. Go to [Railway Dashboard](https://railway.com/dashboard) and click **"New Project"**.
2. Select **"Deploy from GitHub repo"** and pick your repository.
3. Railway will automatically detect the `Dockerfile` and `railway.json`.

### Step 3: Configure Environment Variables in Railway
Under your Railway project **Variables** tab, add the following production variables:

| Variable | Recommended Value | Description |
| :--- | :--- | :--- |
| `APP_NAME` | `Anagkazo Autoparts` | Brand application title |
| `APP_ENV` | `production` | Production environment mode |
| `APP_DEBUG` | `false` | **Crucial for Security**: Disables debug error traces |
| `APP_KEY` | `base64:RhmJXT16Dyx6qQuh37yhbmww25VBEi0BH4aAGRgT2ms=` | 32-character AES-256 encryption key |
| `APP_URL` | `https://${{RAILWAY_PUBLIC_DOMAIN}}` | Public domain generated by Railway |
| `APP_TIMEZONE` | `Africa/Dar_es_Salaam` | Tanzania East Africa Time (EAT, UTC+3) |
| `DB_CONNECTION` | `sqlite` | Default database connection |
| `DB_DATABASE` | `/var/www/html/database/database.sqlite` | SQLite database file location |
| `SESSION_DRIVER` | `database` | Stores user sessions securely in the database |
| `CACHE_STORE` | `database` | High-speed database caching |
| `QUEUE_CONNECTION`| `database` | Asynchronous job processing |

*(Optional)* If connecting a Railway MySQL or PostgreSQL database service instead of SQLite, attach the database plugin and Railway will automatically populate `DB_HOST`, `DB_PORT`, `DB_DATABASE`, `DB_USERNAME`, and `DB_PASSWORD`.

## 🔒 Security Best Practices Implemented

1. **Role-Based Access Control (RBAC)**:
   - **Admin**: Complete system control, stock adjustments, customer registration, reports, database reset, security settings.
   - **Staff**: Streamlined invoice creation and live PDF generation without access to sensitive financials or deletion controls.
2. **Independent Session Logout**:
   - Modifying admin credentials logs out only active admin sessions.
   - Modifying staff credentials logs out only active staff sessions.
3. **HTTP Security Headers in Nginx**:
   - `X-Frame-Options: SAMEORIGIN`
   - `X-Content-Type-Options: nosniff`
   - `X-XSS-Protection: 1; mode=block`
   - `Referrer-Policy: strict-origin-when-cross-origin`
4. **Isolated Zero-Data Leakage**:
   - Local `.env`, `database.sqlite`, logs, sessions, and keys are strictly excluded via `.gitignore`.

## 🛠 Local Development Setup

```bash
# Clone the repository
git clone https://github.com/<your-username>/<your-repo>.git
cd <your-repo>

# Install dependencies
composer install
npm install

# Setup environment & key
cp .env.example .env
php artisan key:generate

# Run database migrations and seeders
touch database/database.sqlite
php artisan migrate --seed

# Build frontend assets
npm run build

# Start local server
php artisan serve
```
